# 골든 작성지침 → 공통 질문 → 일지별 적용 판단 → 연구 근거

## 흐름과 실행

골든 프로파일은 수정하지 않는다. `evidence_requirements.py`가 골든의 참고 절·역할별 작성지침만 받아 주제와 독립적인 공통 질문 파일을 만든다. 연구 주제·프로젝트·연구 일지는 질문 생성과 캐시 식별에 사용하지 않는다. 기존 호출의 scope/profile 인자는 호환을 위해 받을 뿐 무시한다. 초안 작성에는 기존 골든 작성지침도 계속 전달한다.

Streamlit의 **작성지침 → 요구사항 → 근거**에서 **근거 요구사항만 만들기**를 누른다. 연구 주제 입력란은 없다. 이 버튼은 골든 지침만 Upstage에 보내며 연구 PDF를 읽거나 초안을 작성하지 않는다. 화면에서 질문과 적용 조건을 검토하고 JSON을 내려받을 수 있다. 같은 골든 지침·프롬프트의 질문 파일을 여러 연구 일지에서 재사용한다.

- `draft_history/evidence-requirements/<입력 해시>/requirements.json`
- 같은 폴더의 `requirements.md`: 읽기용 질문·필요 항목·출처
- 같은 폴더의 `roles/*/responses/`: 원래 모델 응답과 캐시

이후 어떤 연구 PDF든 선택·업로드하고 **연구 근거만 추출하기**를 누른다. 같은 공통 질문을 읽고, 먼저 `requirement_applicability.py`가 조건부 질문의 적용 여부를 원문에서 판단한다. 그 뒤 `requirement_extraction.py`가 질문에 답하는 근거를 수집한다. 결과는 별도 `draft_history/parse-api-v1/<문서>/research-evidence-requirements-v2/<실행 해시>/`에 저장한다. 공통 질문 사본, `applicability.json`, 원문 아카이브, 모델 응답, 근거와 질문별 충족 검토를 보존한다. 연구별 옛 질문 파일은 새 경로의 추출 입력으로 사용하지 않는다.

기존 복원본은 **기존 전체 수집 → 저장된 연구 근거 불러오기**에서 그대로 읽는다. 두 추출 방식의 결과는 섞지 않는다. Python 호출의 `evidence_mode` 기본값은 하위 호환을 위해 `comprehensive`이고, Streamlit은 새 `requirements` 경로를 기본으로 표시한다.

## 요구사항 계약

- `requirements[].id`: 질문 ID
- `section_ids`: 골든 참고 절 출처. 최종 초안의 고정 목차가 아니다.
- `guideline_ids`: 기존 `reference_catalog`의 criterion ID
- `question`, `expected_fields`: 원문에서 확인할 질문과 필요 항목
- `priority`: 필수 `required` 또는 선택적 문맥 `context`
- `applies_when`: null이면 모든 연구에서 확인, 문자열이면 해당 활동이 있을 때 적용
- `applicability`: 코드가 위 한 값에서 `universal/conditional`과 조건을 계산한다. 별도 이중 선언을 하지 않는다.
- `guideline_dispositions`: 모든 criterion에 질문 변환 또는 작성 전용으로 남긴 이유

골든 논문의 수치·장비·고유 실험을 이번 연구의 필수 조건으로 옮기지 않도록 프롬프트에 명시한다. 단순 문체·서식 지침은 `writing_only`로 남길 수 있다. 질문의 출처 ID·역할·중복 ID·지침별 변환 기록을 코드로 검사한다. 질문이 과학적으로 적절한지는 별도 사람 검토가 필요하다.

현재 생성기는 역할별로 두 논문의 지침을 함께 처리한다. 모델은 각 criterion의 `question_ids`와 사유를 한 번만 선언하고, 코드가 질문의 `guideline_ids`·`section_ids`·`guideline_dispositions`를 계산한다. 출처 지침에 연결되지 않은 부가 질문은 검색 질문에서 제외하며 원응답에는 남긴다. `section_ids`는 역할별 지침의 출처이지 골든 소절별 독립 의미 검토 결과가 아니다. 원본 절 제목은 로컬 출처로 보존하며 생성 입력에서는 제외한다.

## 연구 일지별 적용 판단

일지의 원문을 구간별로 읽고 조건의 성립·미성립 단서를 원문 ID에 연결한다. 후보 단서는 질문별로 다시 판단한다. 원문에 명시적 미수행 기록이나 조건을 배제하는 근거가 있어야 `not_applicable`로 분류한다. 구간에 언급이 없다는 것만으로 해당 없음 처리하지 않는다. 단서가 없거나 상충을 해결하지 못하면 `uncertain`이다. 공통 질문 자체는 수정하지 않으며 일지마다 별도 판단 결과를 저장한다.

`universal` 질문은 정의상 적용된다. 답이 없으면 근거 부족이다. 조건부 질문이 `not_applicable`이면 추출 대상에서 제외하고 작성 누락으로 세지 않는다. 적용 미확인 질문은 근거를 더 찾을 수 있도록 검색에 남기되 자동으로 근거 부족·해당 없음으로 확정하지 않는다.

질문별 화면과 JSON은 `sufficient`(충족), `partial`(일부 부족), `missing`(적용되나 근거 부족), `not_applicable`(해당 없음), `applicability_uncertain`(적용 여부 미확인)을 구분한다. 판단 사유와 실제 원문 인용을 보존한다. 적용 여부 판단은 모델 보조 검사이며 독립적으로 참임이 보장되는 것은 아니다.

## 추출과 중복

사실 하나에 여러 `requirement_ids`를 연결한다. 이전 페이지에서 찾은 같은 내용은 기존 사실 ID에 출처와 질문을 추가할 수 있다. 내용·조건·관측·측정 필드가 정확히 같은 후보는 코드로 병합한다. 조건이나 결과가 다르면 병합하지 않는다. 유사 표현의 의미 중복이 모두 제거된다는 보장은 없다.

페이지 추출에는 적용 여부의 상태만 전달하며 적용 판단의 다른 페이지 원문·사유를 다시 넣지 않는다. 현재 대상 원문 ID와 앞뒤 문맥 ID를 구분한다. 기존 근거가 없으면 `existing_links`는 빈 배열로 제한한다. 페이지의 모든 출처·질문·재사용 연결을 검사한 후에만 공유 근거를 갱신한다. 오류 시 구체적 사유로 현재 페이지 전체를 1회 보정하고, 다시 실패하면 `pending_extraction_pages`로 보류하여 작성 게이트를 유지한다. 원응답과 검증·정규화 기록은 `pages/page-XXXX-validation.json`에 남긴다. 페이지 응답의 요청 식별자는 새 입력·프롬프트에 따라 달라지며, 완료된 일지별 적용 판단은 재사용한다.

페이지 API는 회당 최대 120초 대기한다. 응답 읽기 시간 초과(`ReadTimeout`)만 낮은 추론 설정으로 1회 재시도하며, 그 외 실패는 페이지 번호를 표시하고 중단한다. 성공한 대체 응답은 재개 시 우선 재사용한다. `pages/*-transport.json`에 시간 초과 이력과 대체 호출 완료 여부를 저장한다. 검증 실패 보정 요청에도 같은 제한이 적용되므로 재시도가 무한 반복되지 않는다.

중간 결과는 실행 폴더 `responses/requirement-page-*.json`의 `value`에 저장되고 `pages`에는 검증 기록, `applicability.json`에는 적용 판단이 있다. 전체 추출과 검토가 끝나기 전에는 최종 `evidence.json`이 없을 수 있다. 중간 후보는 아직 독립 원문 검토가 끝난 작성 허용 근거와 다르다.

질문 밖의 중요한 새 결과·실패·반대 결과·한계는 `supplemental_reason`을 붙여 보존한다. 원문 요소별 무조건 수집·누락 복구 루프는 실행하지 않는다. 전체 원문은 아카이브에 남긴다. 검색 범위는 PDF 전체이며 모델 호출 수와 비용 감소는 아직 실측하지 않았다.

기존 `ground` 수치 검사와 `verify_page` 독립 원문 검토를 재사용한다. 계획·가설·해석·AI 조언은 해당 성격을 유지한다. 검증된 근거로 질문별 충분성을 별도 모델 호출에서 평가하며 `sufficient/partial/missing`, 근거 ID, 부족 항목, 사유를 저장한다. 표는 실제 원문에서 구조화되고 허용 근거에 연결된 표만 작성 입력에 넣는다.

## 작성과 제한

### 사용자 지시를 받고 재개하기 · 2026-11-03

질문 충족 검토에서 `missing`인데 근거 ID가 연결되는 등 판정이 모순되면 오류 종료 대신 `RequirementInterruption`으로 질문별 판단 대기 상태를 저장한다. 작성 계획·초안을 요청했을 때 필수 질문의 근거 부족·적용 미확인이 남은 경우도 같은 입력 화면으로 이어진다. `연구 근거만 추출하기`는 정상적인 부족 판정 결과를 그대로 조회할 수 있다.

화면은 질문·부족 항목·AI 판정 사유·검토 근거를 보여주고 자유로운 처리 지시를 받는다. 지시를 별도 모델 호출로 `exclude/provide_information/recheck/clarify` 중 하나로 해석한다. 제외는 그 질문에만 적용하고, 추가 기록은 입력 메시지의 실제 문자열을 별도 `user_addendum` 출처로 보존한다. 추가·재탐색 근거도 수치·원문 대조와 질문 충족 검사를 거친다. 재탐색은 저장된 연구 원문에서 지정 페이지 또는 전체를 다시 검색한다. 불명확한 지시는 저장·적용하지 않고 다시 질문한다.

- `pending-question.json`: 대기 질문과 원래 판정. 원래 API 응답을 고치지 않는다.
- `human-decisions.json`: 사용자의 원문 지시·해석한 동작·질문 ID·시간을 순서대로 보관한다.
- `assessment-input.json`: 추출·원문 검토가 끝난 입력과 해시. 답변 이후에는 질문 검토부터 재개한다.
- `interrupted-request.json`: 계획만 생성/초안 생성 등 중단된 요청을 보관한다. 선택한 PDF·질문 파일이 같으면 새로고침 후에도 입력 화면을 복원한다.

`excluded_by_user`는 원문에서 해당 없음이 검증됐다는 판정과 다르다. 자동으로 `sufficient`로 승격하지 않는다. 계획·작성·검토 입력에 사용자 지시를 전달하며, 제외 질문에만 연결된 골든 필수 기준도 작성 지침에서 제거한다. 다른 활성 질문과 공유하는 기준은 유지한다. 추가 정보는 사용자 보고와의 일치 검토이며 PDF 근거나 독립 검증으로 표시하지 않는다. 판독 불가·출처 검증 실패 등 질문 밖의 작성 제한은 그대로 유지한다.

이 기능 이전에 실패한 실행에는 체크포인트가 없을 수 있다. 기존 `requirement-check-*` 모순 응답을 먼저 질문 화면으로 복원하고, 지시 후 저장된 추출 응답을 재사용한다. 입력이 일치하는 완료 캐시만 재사용하므로 최초 재개 때 원문 검토의 일부 API 호출이 다시 필요할 수 있다. 사용자 지시는 실제 입력 전까지 대신 작성하거나 적용하지 않는다.

작성 입력에는 원래 골든 지침, 공통 질문, 일지별 적용 판단, 질문별 충족 상태, 공유 근거 ID를 보존한다. 필수 질문의 근거가 부족하거나 적용 여부 미확인·검증 실패 후보·판독 불가 원문이 있으면 본문 작성을 제한한다. 해당 없음은 작성 누락으로 취급하지 않는다. 필수 적용 미확인은 `unresolved_applicability_ids`, 적용되나 부족한 질문은 `unresolved_requirement_ids`로 별도 집계한다. 한 질문 안의 조건부 하위 항목도 실제 수행한 활동에만 요구한다.

새 완료 상태의 `scope=evidence_requirements`는 질문 범위의 검토다. 기존 전체 수집의 원문 요소별 완전성 검토와 다른 의미이며, 기존 저장본의 `ready_for_drafting=false`를 변경하거나 해제하지 않는다. 새 화면은 읽기 전용이며 기존 전체 수집용 복구·사람 승인 함수로 상태를 덮어쓰지 않는다.

## 검증 범위

모델을 대체한 자동 테스트로 요구사항 출처·독립 파일 저장, 질문 전용 실행의 PDF/작성 미호출, 여러 질문의 근거 공유, 조건 차이 보존, 검증 실패·근거 부족·판독 불가 시 작성 제한, 입력 변경 시 저장본 구분을 확인한다. 실제 문서 전체의 새 추출 품질은 아직 평가하지 않았다.

2026-11-02 현재 공통 후보는 `draft_history/evidence-requirements/a14bc74dc9c6736cf6c6/`: 골든 지침 55개에 공통 질문 52개(항상 확인 25·조건부 27)를 연결했다. 연구 주제 필드가 없고, 질문·필요 항목에서 CUDA/NPU/RGB/묘목 등 앞선 후보의 고유 주제 표현이 검출되지 않음을 확인했다. 이는 의미 일반화 전체를 검증한 성능 수치가 아니다. Streamlit은 주제 입력 없이 캐시로 이 파일을 표시한다. 이전 연구별 후보와 초기 공통 후보는 그대로 보존했다.

같은 질문 파일에 합성 일지 세 종류(학습 미수행 명시, 학습 수행했으나 설정 근거 누락, 수행 여부 불명)를 넣어 해당 없음·근거 부족·적용 미확인과 작성 게이트가 각각 구분됨을 확인했다. 사용자 실제 실행에서는 적용 판단 이후 첫 페이지 재사용 연결 오류가 발생해 검증·보정·보류 경로를 보완했다. 외부 호출을 차단한 실제 캐시 재생은 첫 페이지 요청까지 성공했다. 전체 추출 완료·실제 문서 품질·호출 수·중복 감소율은 아직 평가 전이다.
