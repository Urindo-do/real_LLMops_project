# 미확인 근거 복구와 승인 근거 중복 연결

2026-11-01 구현. 현재 식별자: `research-pending-recovery-v2`.

## 사용

새 v3 추출은 기존 원문 수집·대조 후 미확인 근거 복구를 실행한다. 기존 저장본은 연구 근거 화면의 **미확인 근거 복구·중복 연결 검토** 버튼으로 실행한다. 저장본을 불러오는 것만으로 모델을 호출하지 않는다.

버튼은 왼쪽 메뉴의 **저장된 연구 근거 불러오기** 바로 아래에도 있다. 현재 불러온 근거가 없으면 선택한 input 자료의 저장본을 읽은 뒤 복구한다. 저장본 또는 선택 자료가 없으면 비활성화된다. 2026-11-01 실행 중이던 앱에서 예전 화면이 유지돼 앱을 재시작했고, Streamlit AppTest로 왼쪽 메뉴와 근거 결과 양쪽에 버튼이 렌더링되는 것을 확인했다.

코드는 승인 근거 중 출처·문장이 겹치는 후보를 최대 3개 찾는다. 페이지별 최대 4개 사실을 묶고 최대 4개 묶음을 병렬 검토한다. 최초 제안이 코드 검사에 실패하거나 unresolved면 구체적인 실패값·필드와 이전 제안을 넣어 수정 요청을 한 번만 더 한다. 통과한 제안은 별도 검증을 거치며 실패 시 원래 근거를 유지한다. 빈 JSON 묶음은 관련 출처로 문맥을 좁혀 절반씩 나누고, 단일 항목도 실패하면 원래 사실과 사유를 보존한다. 서비스 호출 계층의 JSON 형식 재요청·추론 설정 fallback은 기존 정책을 따른다.

v1 실사용 결과는 복구 16개·중복 연결 제안 12개·미해결 220개였다. 미해결 60건은 repair에 참고 대표 ID가 같이 포함돼 형식 검사가 거부한 것이었다. v2는 이 ID를 참고 이력으로 받되 수치·내용 보존·독립 원문 검사를 모두 요구한다. 50건의 수치·출처 실패에는 구체적인 오류를 수정 담당에게 되돌려 준다. 독립 검토의 claim_status/source_origin은 enum으로 제한해 `observed (preserved)` 같은 부적합한 값도 방지한다.

독립 검토에서 내용 손실을 발견한 repair도 보정 기회를 아직 사용하지 않았으면 해당 지적을 넣어 한 번 수정한다. 코드 검증 보정과 내용 보존 보정은 사실별로 합계 1회를 넘지 않는다. 수정된 안은 독립 검토를 다시 통과해야 한다. 원문에서 확인된 측정값·설정의 삭제·변경 차단은 유지한다.

UI의 **미해결 항목이 남은 이유**에서 응답 실패·형식·수치 출처·내용 보존·중복 관계·원문 뒷받침 문제를 나눠 볼 수 있다. 진행 보고서는 status=running으로, 최종 보고서는 completed/partial로 저장한다.

## 판정과 반영

- `support`는 해당 주장의 원문 충실성이다. 계획의 실제 완료, 작성자 관찰의 독립 검증, 원문에 없는 재현 조건을 요구해 기록 자체를 기각하지 않는다. 남은 연구의 한계는 `evidence_limitations`에 보존해 작성 입력에도 전달한다.
- 수치·버전·귀속·조건이 불명확한 후보는 필요한 출처를 연결하거나 잘못 추출된 부분만 수정한다. 이전 검사 오류와 수정 이력은 연구의 `limits`에 복사하지 않는다.
- 수정안은 수치 검사와 독립 검증을 모두 통과해야 같은 사실 ID에 반영된다. 이미 승인된 측정·설정의 삭제·변경은 코드가 차단하고, 원문이 뒷받침하는 주장의 손실은 별도 검토자가 검사한다. 미확인 수치나 거부된 측정값이 남은 후보는 중복 처리로 우회할 수 없다.
- 완전 중복은 추가 정보 없음·높은 확신·승인된 대표 근거를 확인한 뒤 사람에게 연결을 제안한다. 확인 필요 항목 안에서 대표 문장과 원문을 보고 **대표 근거에 묶고 중복 항목 제외**를 선택한다. 사람의 결정은 기존 제외 이력으로 저장돼 복원할 수 있다.
- 부분 중복은 전체를 제외하지 않는다. 승인된 근거를 참고해 아직 확인되지 않은 내용을 복구한다. 사람이 승인·제외하거나 대표를 결정한 사실은 자동 수정하지 않는다.
- 수정된 사실의 출처 페이지와 사람이 중복 연결한 페이지는 수집 대장을 다시 검사한다. 이 검사는 새 사실을 추가하지 않는다. 미해결·판독 불가·미검토 요소·별도 이미지 오류가 남으면 작성 게이트는 닫힌다. 대장 재검사가 실패해도 해당 페이지를 미해결로 보존한다.

## 기록과 제한

원문 아카이브는 유지한다. 실행별 `pending-recovery/<입력 해시>/recovery-report.json`에 원래 사실·수정 제안·독립 검증·반영 결과를 남긴다. `evidence_recovery`는 마지막 실행이고 이전 보고서 경로는 `evidence_recovery_history`에 남는다. 사람의 중복 연결 후 대장 검토는 `duplicate-source-rechecks/`에 별도로 저장한다.

근거가 바뀌면 해당 의미 중복 묶음은 무효화한다. 예전 사람의 대표 선택도 현재 사실의 지문과 일치해야 적용된다. 대표 근거가 동시에 수정된 중복 제안은 다시 미해결로 돌린다.

후보 검색은 문장·출처 유사도에 기반하므로 표현이 크게 다른 중복은 놓칠 수 있다. 본 구현은 자동 검토 기준과 복구 경로를 개선한 것이며, 실제 CUDA 문서에서의 복구율은 새 모델 실행으로 별도 평가해야 한다. 개발 검증은 외부 API를 사용하지 않는 회귀 테스트로 수행했다.
